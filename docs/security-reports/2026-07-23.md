- `.env`/서비스계정/`.key`/`.pem`이 git 히스토리(`--all --diff-filter=A`)에 커밋된 적 없음. 추적되는 env 파일은 `.env.emulator`(비밀 아님 플래그)와 `.env.local.example`(플레이스홀더)뿐, `.gitignore:17-71` 차단 + `!` 화이트리스트로만 예외.
- 하드코딩 스캔: `AIza…`는 `public/firebase-messaging-sw.js:10`의 Firebase 웹 apiKey(공개 설계상 정상, 제외), `xoxb-`는 테스트 픽스처(`functions/src/__tests__/`)만. Discord 웹훅·`GOCSPX-`·`ghp_`·`AKIA`·PRIVATE KEY 없음.
- 백엔드 시크릿은 `functions/src/core/params.ts:17-44`에서 전부 `defineSecret()` → Secret Manager. CI는 `${{ secrets.* }}`로만 주입.

### Phase B — 멀티테넌트 / 인가 격리 (OWASP A01) ⭐ (VERIFIED 클린)
- `firestore.rules`: 7종 tenant-scoped 컬렉션(vehicles·hipassCards·driveLogs·reservations·fuelLogs·hipassCharges·maintenanceRecords) 모두 `belongsToMyOrg()` 게이트 + update 시 `organizationId` 불변 강제(#6 조치 유효). 서버 전용 컬렉션(`users/{}/private`, `orgStats`, `integrations`, `slackUsers` 등) `if false` 봉인.
- 권한 상승 차단: `users` update가 자기 `role`/`organizationId` 변경 금지, admin의 `superAdmin` 부여·타 org 이전 불가. `setCustomClaims` 트리거가 미지 role을 `employee`로 강등.
- Cloud Functions: 모든 callable이 `context.auth` 재검증 + 역할/org를 **caller 자신의 클레임/유저 문서**에서 도출(클라이언트 `role` 불신). 예약 코어는 트랜잭션 내 `actorOrgId === reservation.organizationId` + 차량 org 일치 + 소유자 확인. Slack 체인은 HMAC 검증 → `getSlackIntegration(teamId)` → `resolveSlackUser`가 org 불일치 유저를 캐시 히트에서도 거부.
- Storage: 기관 문서 PII는 `read: if isSuperAdmin()`, `write:false`(서명 URL로만 제공).

### Phase C — Gemini OCR / LLM ⭐ (VERIFIED 클린)
- 프롬프트 인젝션 특권 싱크 없음: OCR이 보안 결정을 내리는 유일한 곳 `autoVerifyDocument`도 `documentType` 하드 enum 화이트리스트로 off-list 값은 `"기타"` → 수동 심사로 강등, `orgName`은 `sanitizePromptValue`로 정화(60자 캡). `parseIntent` LLM 출력은 intent 화이트리스트·정규식·실제 차량 멤버십으로 서버 재검증.
- 저장형 XSS 없음: `src/` 전체 `dangerouslySetInnerHTML`/`innerHTML` 0건. AI 응답은 React 평문 렌더(자동 이스케이프).
