# 차량 운행일지 — 구현 이력 (Phase별 색인)

> [차량운행일지_구현계획서.md](차량운행일지_구현계획서.md) §17에서 분리한 전체 Phase 이력의 **색인**이다. 살아있는 설계·레퍼런스는 구현계획서 본문에 있고, 이력은 **append 전용 과거 로그**다.
>
> 단일 파일이 270KB를 넘어 사람이 읽기 어려워져 구간별로 분할했다(2026-07-25). 본문은 아래 5개 파일에 있고 이 파일은 색인만 유지한다. 기존 문서·링크가 이 경로를 가리키므로 경로는 그대로 둔다.

## 새 Phase는 어디에 추가하나

**[트랙B_Phase181부터.md](구현이력/트랙B_Phase181부터.md) 끝에 append**한다.

열린 구간이라 파일명이 `…부터`로 끝난다. Phase마다 리네임하면 링크가 깨지므로, 200KB에 가까워졌을 때 최종 범위명으로 **한 번만** 리네임하고 새 `…부터` 파일을 만든 뒤 이 색인에 한 줄 추가한다(직전 분할: `트랙B_Phase142부터.md`를 2026-09-02에 231KB에서 닫음 — 이미 200KB를 넘긴 뒤라 리네임만으로는 기준을 지킬 수 없어 내용을 갈라 `트랙B_Phase142-180.md`(143KB) + 새 `트랙B_Phase181부터.md`로 나눴다. 그 전: `트랙B_Phase103부터.md` → `트랙B_Phase103-141.md`, 2026-08-03에 188KB에서 닫음).
추가 후 [차량운행일지_구현계획서.md](차량운행일지_구현계획서.md) §17 포인터·메타를 함께 갱신한다.

## 두 개의 번호 트랙

시기가 겹쳐 단일 연속 번호로 합치면 이력이 왜곡되므로 트랙을 분리 표기한다.

- **트랙 A** — 초기 상세 이력 Phase 1~58 (~2026-05-29). 이 중 Phase 49~57은 2026-05-29 git 로그 기반 사후 복원분.
- **트랙 B** — 운영 고도화 로그 Phase 49~ (2026-04-15 ~). 원래 구현계획서 §18 아래에 잘못 중첩돼 있던 것을 분리한 뒤 계속 append한다.

두 트랙 모두 Phase 49~57(58) 구간이 존재하는데, 같은 시기를 서로 다른 관점(트랙 A=상세 복원 / 트랙 B=고도화 로그)으로 기록한 것이다. **Phase 번호만으로는 파일이 특정되지 않으므로** 이 구간은 아래 표에서 트랙을 먼저 고른다.
